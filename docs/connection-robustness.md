# Diagnose a lost SAP connection

`healthcheck` without arguments checks only the MCP process and retains its existing `status` and `timestamp` response. To test SAP explicitly, call `healthcheck` with `{ "probeSap": true }`. This starts one authenticated, read-only ADT discovery GET on an **independent stateless session**. The healthcheck response has a five-second deadline covering authentication and the GET; the GET also has a five-second request timeout. The deadline does **not** cancel an underlying login or request that remains pending. A successful probe does not prove that the editing session or its locks remain valid. A failed probe returns a safe category (`authentication`, `network`, `sap_http`, or `unknown`, or `timeout`), and a bounded HTTP status or recognized network code when available; it does not return cookies, credentials, request configuration or SAP response bodies.

Core source read/write, lock/unlock, and login/logout/dropSession failures return standard MCP `isError` results with a safe `diagnostic` (`category`, and when available an allowlisted HTTP `status` or network `code`). Neither ADT error text nor request configuration is returned. Other MCP errors retain their existing payload. A subsequent tool call remains possible; this does not establish that the SAP editing session is valid.

If a tool loses its session, inspect the object and locks in SAP before repeating any write: the write may already have taken effect. Recovery is explicit: use `dropSession`, then `login` when appropriate, and reacquire locks deliberately. Neither the server nor the health probe replays writes, silently switches off stateful editing, or replaces locks. Switching clients affects subsequent requests; an already-running request retains its original ADT connection. Cached source for syntax checking belongs only to the connection on which it was read or written, and a client reload starts with an empty cache for the new connection.

These offline checks simulate errors; they do not reproduce the reported third-call incident. Obtain the exact host error and timestamp to identify its real cause.
